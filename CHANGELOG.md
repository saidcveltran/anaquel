## [0.2.1] - 2026-11-20

This release adds the first phase of the local editor, `anaquel studio`. It is numbered 0.2.1 and not 0.3.0 because it does not change the library format or the engine line: a library with `engine = "0.2"` opens as before, and nothing in `anaquel.toml` has to be edited. Before 1.0 a new minor would have made every such library refuse to open.

### Added

- Design page `docs/decisions/0006-studio-phase-one.md`: how phase 1 of the web panel (`anaquel studio`, local and single user) is built and cut into pieces, with the tests it requires; proposed, nothing built. Its main points: paths as a checked type, an atomic save with a stale-text check, a preview that is the build with one page's text replaced, and request guards (`Host`, `Origin`, a random token) because any web page can send requests to `127.0.0.1`. Unmeasured: how fast an analysis per pause in typing is on a large library.
- `anaquel_pipeline::preview_page(root, page, text)`, piece 2 of that design: the page as the site would serve it when its text is `text`, without writing anything. It reads the library, puts the text of the editor in the place of the page (or adds the page, when it is inside a volume folder but not on disk yet), resolves the catalog as `build` does, and composes and renders that one page with the same theme and templates. It returns the diagnostics that name the page, those of the rest of the library apart, the address of the page, whether it is a draft (a draft is rendered for the editor), and the HTML, which is `None` when the page has an error: an error never gives a page that looks like the site. `theme_assets()` returns the stylesheets and other files the HTML refers to, under the same fingerprinted names; the asset loop of `build` moved to one function that both use. A text larger than the build reads (5 MiB, now the public constant `MAX_PAGE_BYTES`) is refused before it is parsed. What ingest says about the copy on disk of the page (too large, not text) is dropped, because the text of the editor replaces that copy; the rules about the name (`#`, `%`, `?`, a leading dot, a Windows-forbidden character) are checked again on the name itself. A diagnostic of the catalog belongs to the page when it names the page or when the new text introduced it (it is absent from the catalog of the disk state); a clash that was already on disk is reported under `elsewhere`, not blamed on the page. `PagePreview.frame_origins` lists the origins of the frames the page embeds, so the server can allow them in its policy. The folder of the library is replaced by `<library>` in every message. Tests (26): the preview of a text is byte for byte the page that `build` writes when that text is saved on disk; the page diagnostics are the ones `check` gives; nothing is written; a byte order mark and `\r\n` change nothing; a broken link, broken front matter, an unknown key, an unknown directive and raw HTML give diagnostics and no HTML; a problem in another page is kept apart and does not stop the preview; a new page that takes the address of another is an error of the new page, while a clash already on disk is not; an unreadable file on disk does not stop its replacement; drafts, a page not on disk yet, a page in a shelf, a page name in another Unicode form, an index page and a capital `.MD` are previewed; and paths that are not pages of a volume (`anaquel.toml`, a file straight under `volumes`, `../`, a leading `/`, a backslash, a name that starts with a dot, a name with `#`, `%` or `?`, and others) are refused with a reason; two previews in a row share nothing; the largest example (271 pages) previews with no diagnostic. Measured on this Windows PC in a debug build, on that example: about 120 ms for each preview (118.9 to 127.9 ms over five) after a first one of about 740 ms (the theme and the highlighter start), against 92 ms for `check` of the whole library; a release build was not measured. Limits: only the page is composed, so the links and directives of other pages are not checked and `elsewhere` holds only what reading the library and resolving the catalog find (`check` finds the rest); the catalog is built twice per call (disk state, then with the text) and the theme and the template engine are loaded on every call, which is the first thing to cache if 120 ms is too slow in practice; the library is read from disk on every call, so a file that another program changes between two previews shows the change; drafts are rendered for the editor and search is not part of the preview, so both differ from the built site on purpose; the HTML uses the absolute addresses of the site (`/assets/...`, `/guide/setup/`), so the server that shows it has to serve them at its root or rewrite them.
- `anaquel-studio`, the core of the local editor planned in `docs/decisions/0006-studio-phase-one.md` (piece 1 of 5; there is no `studio` command and no HTTP yet, so nothing a user can run changes). It holds three parts. `LibraryPath` is a path inside a library that can only be built from a relative path of plain names: it refuses an empty or longer-than-1024-byte path, a leading `/`, a drive, a backslash, `:` (alternate data streams), `.`, `..` and empty names, names that start with a dot (the build skips them), names that end in a space or a dot, the Windows device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1`-`COM9`, `LPT1`-`LPT9` with any extension, on every system, so a library made on Linux opens on Windows), the characters `< > " | ? * # %` and control characters, a name over 255 bytes, a file used as a folder, and any name on the way that is a symbolic link or that resolves outside the library. `list_pages` lists the pages of `volumes/` and `shelves/NAME/volumes/` with shelf, volume, title, draft or invalid front matter, size and last change, by the rules of the build: a folder is a volume or a shelf only when its name is a URL segment and its `volume.toml` or `shelf.toml` is valid (otherwise it is left out and a line in `problems` says why, as the build reports it), dot names are skipped, a link to a folder is followed as the build follows it but the pages behind it are listed as unavailable and are never read, and `.md` is matched in any case. A page the editor cannot open is listed with the reason instead of being hidden, and a temporary file that an interrupted save or move left is reported in `problems`. `read_page` and `save_page` read a page as the library reads it and save it only if the file still has the SHA-256 `Revision` the editor loaded; a page edited by another program in between is refused with `Stale` and left untouched, a saved page keeps its byte order mark and its `\r\n` line ends, and the revision a save returns is the hash of the bytes the write reported, not of a second read. Refused: a page that mixes both line ends; a page that would be over 5 MiB once written (the line ends and the byte order mark that the page keeps are counted, so a 3 MB text of `\n` in a `\r\n` page is refused, where it would have been saved as 6 MB and could not be opened again); a read that grows past 5 MiB; text that is not UTF-8 or holds a NUL; a carriage return that does not end a line (`\r\r\n` and a lone `\r`, which one pass of `\r\n` to `\n` would have turned into a page that mixes line ends) and a leading byte order mark in the text; a page already in one of those states cannot be opened, so nobody edits a text the save would change or refuse; and a file that is not a page (`anaquel.toml`, `volume.toml`, a file straight under `volumes/`). A save never creates a page.
- `anaquel_pipeline::rewrite_page`, the write behind `save_page`: it replaces the text of one existing page through the disk layer that `relocate` already uses (a staged file made with `create_new`, the permission bits copied, a rename, every failed step undone and every file that cannot be put back named), so the editor does not carry a second copy of that logic. It returns the bytes it wrote. A page that changed since the caller read it returns `RewriteError::Changed`, told from a failure of the disk by a marker inside the error instead of by its text; a page that mixes line ends or would be too large returns its own error. A staged name that is already taken (by a file a crash left, or by another save in progress) is never written through: the next of sixteen names is tried, and a leftover is not deleted, because it cannot be told from the staged file of a save that is still running. Also public: `MAX_PAGE_BYTES` (the 5 MiB limit of the build, now one constant instead of two) and `is_temporary_file_name`.
- Tests: 58 in `anaquel-studio` and 12 on `rewrite_page` on Windows, two more on Unix (every refused form of a path, each with an accepted counterpart; links that point inside, outside and at a file, made as junctions on Windows when a symbolic link is not allowed; the list with drafts, bad front matter, BOM and CRLF, a 5 MiB page, bad folder names, bad manifests, leftovers and a folder that cannot be read; reading, saving, staleness, line ends, size with and without expansion, NUL, a lone `\r`, a leading mark, each failure of the write mapped to its own error, a revision taken from the written bytes, a read-only page, a page that became a link after the path was checked; for `rewrite_page`, a write interrupted at each of its three steps leaves the old page, a clean-up that also fails names the file left behind, a taken staged name is skipped and its file is untouched, sixteen taken names leave the page as it was). The independent review of the first version of this piece found two bugs (the size limit measured the text, not the file that would be written; `\r\r\n` left a `\r\n` behind) and five weaknesses; each is fixed here and has a test. Limits: the test of a link to a file needs a privilege on Windows and runs on Linux in CI, where the permission-bit test also runs; the `Outside` error of a path (a folder that resolves outside the library without being reported as a link) has no test, because Windows reports a junction as a link and Linux has no equivalent; the check that a path has no link and the write that follows are separate calls, so a folder replaced by a link between them is not caught (the same limit `relocate` documents); a page edited by another program between the comparison and the rename is lost, and the editor cannot tell; on NTFS with short names enabled, a hidden page can be reached by its short name, always inside the library; `list_pages` reads and parses every page each time it runs, which costs a read of the library per call; `LibraryPath` keeps the name as written, while the build compares names in NFC, so a caller that compares paths must do the same.

- The HTTP layer and the interface of `anaquel studio` in `anaquel-studio`, piece 3 of the design (`Studio::start` and `StudioConfig`; there is still no `studio` command, so a user cannot run it yet). The server binds `127.0.0.1` only, on a port given or chosen by the system, and answers: the interface under `/__studio/` (one HTML page, one script and one stylesheet, embedded in the program, with no framework and no build step); `GET /__studio/api/pages` (the list), `GET /__studio/api/page?path=` (text and revision), `PUT /__studio/api/page` (save with the revision the editor loaded; `409 stale` when the file changed), `POST /__studio/api/preview` (the page for the text sent, from `preview_page`); and the stylesheets, scripts and images of the theme under `/assets/`, from the files `theme_assets()` returns, never from the disk. Every request passes the guard of decision 6 before a route runs: `Host` must be `127.0.0.1:PORT` or `localhost:PORT` and appear once (against DNS rebinding); a 256-bit key made with the system generator, printed once in the address the program opens, is accepted in the address at one route only (`/__studio/enter`), where it is traded for a cookie (`HttpOnly`, `SameSite=Strict`) and the browser is sent on without it; any other route that has the key in its address is refused, so it does not end up in a bookmark, a log or a `Referer`; the key is compared without stopping at the first different byte; a change or a preview needs `Origin` to be the server itself (a missing one is refused), `Sec-Fetch-Site` not to say another site, and `Content-Type: application/json`, which a form from another site cannot send. A refusal says what to do (JSON for the page; a small page for a browser that was sent here by hand). Every answer, refusals included, carries a `Content-Security-Policy` with no inline script or style and no `unsafe-*`, `nosniff`, `no-referrer`, `no-store`, `X-Frame-Options: DENY` and `Cross-Origin-Resource-Policy: same-origin`. The interface lists the pages by shelf and volume with a filter, edits the text in a `<textarea>`, previews on a pause of 400 ms in typing (a late answer never replaces a newer one), keeps the last page that built while the text has an error, shows the diagnostics of the page and those of the rest of the library apart, saves with the button or Ctrl+S, asks in the page (not with a dialog) what to do when the file changed on disk or when another page is opened with unsaved changes, warns before the tab is closed with unsaved changes, and inserts the text of nine directives (hint in three kinds, details, tabs, cards, steps, columns, embed). Its texts are in English and Spanish, chosen by the browser and switchable, and a test fails if a key exists in one language and not in the other, if a placeholder is lost in a translation, if the page or the script uses a key that does not exist, or if a text is never used. The preview is shown in a frame with `sandbox="allow-same-origin"` and no `allow-scripts`, so nothing in a page runs, and the links inside it do not navigate. Tests (80 new, 138 in the crate): real sockets on port 0 with a client that writes the request by hand, so a test can send a second `Host`, a foreign or `null` `Origin`, a cross-site `Sec-Fetch-Site`, a wrong content type, a wrong or missing cookie, the key where it does not belong and a path such as `../anaquel.toml`, `%2e%2e`, `\` or `C:\`, each on every route and each leaving the page untouched; the same requests with the right values are accepted; two saves from one revision at once give exactly one `200` and one `409`; the key never appears in a body or a header other than the cookie of the entry; every file the preview links is served; a body of 12 MiB of control characters (the largest a page can be as JSON) is accepted. Five changes to the guard were made on purpose to check that the tests can fail (no `Host` check, writes with no `Origin`, the key accepted in any address, any cookie accepted, the security headers dropped): each failed between one and six tests, and the guard was restored byte for byte. Limits: the interface was written and tested through its text (keys, no inline code, no `innerHTML`) and through the server, and was then driven in a browser once (see the entry on the first use, below); the frame shows an embedded video without scripts, so it does not play; the cookie has no `Secure` attribute because the address is `http`; the key is in the terminal that started the program (and in its scrollback), and any program of the same user that can read it can use the studio; another user of the same machine can reach the port but has no key; there is no limit on connections or on how slowly a client sends; the body limit is 6 times 5 MiB plus 4 KiB; the save lock is per process, so a second `studio` on the same folder is protected only by the revision check; a preview takes about 120 ms (see the piece 2 entry), run on a blocking thread so it does not stop other requests.

- `anaquel studio [ROOT] [--port N]`, piece 4 of the design: starts the editor of the previous entry on the library folder (default: the current one) and prints one address that carries the key; the person opens it in the browser of the same computer. The port is chosen by the system unless `--port` gives one. A folder that does not exist or has no `anaquel.toml`, and a port that is taken, end with a message (the last with a hint to use `--port`), exit code 2 and nothing printed on the standard output, so no address is shown for a server that is not running. `anaquel doctor` says the editor is built in. The README rows (English and Spanish) say what it is, that it is not in any release and that nobody has used it in a browser yet. Tests (7, on the real program): the printed address opens a session (a `303` to the interface and the cookie, with `HttpOnly` and `SameSite=Strict`), the same route without the key gives `401` and does not repeat the key, a second run has another key, `--port` is honoured, and the three failures above. Limits: the process stops only when it is killed (Ctrl+C); the key is printed in the terminal; the program does not open the browser by itself.

- First use of `anaquel studio` in a real browser (Chrome on Windows, 2026-11-20, on a copy of the 271-page example library), and the two defects it found, which the tests of the previous entries could not see. Verified by hand: the list of pages, opening a page, the live preview with the theme, an error in the text (`AQ0302` with its line, and the last good page kept with a note), saving with Ctrl+S, a save refused after another program changed the file (the message, the choice to load the disk version, the file on disk untouched, and the disk version loaded), the directive menu, and the switch of language. Defects fixed: (1) clicking a link inside the preview took the frame to a blocked page, because the guard against it asked `instanceof Element`, which is false for a node of the frame (it has its own `Element`); it now asks the node for `closest`, and a test forbids `instanceof` on nodes; (2) the list showed a dozen entries all called `_index.md`; a page without a title now shows its path inside the volume (`foundations/_index.md`). Also: `anaquel studio` printed the folder as `\\?\C:\...` on Windows (the form `canonicalize` returns); it now prints `C:\...` (`plain_path`, with tests for a drive, a network share and the forms it leaves alone). After the fixes, a click on a link in the preview was tried in the same browser (a build of this branch): the frame stayed on the preview, its document was still reachable and its title unchanged; the list with paths was seen in the same run. Limits found and left: the messages of diagnostics are in English whatever the language of the interface, because they come from the engine; a navigation started by the browser tool (not typed or pasted) is refused with `bad_origin`, (inferred from the refusal, the header was not captured: the browser reports such a navigation as coming from another site), so the studio is opened by pasting the printed address; the directive menu and the language switch were driven by script, not by clicks; only one browser, one computer, one library were tried.

### Fixed

- Two tests of the download client in `anaquel-upgrade` failed together on one run of the CI (`ubuntu-22.04-arm`) and passed on the earlier run of the same code: `a_port_with_nobody_listening_fails_and_does_not_hang` released a port and then connected to it, and the system had already given that port to the scripted server of another test running in parallel, so the client consumed that server's only reply (`TooLarge`) and the other test's client got `Connection reset by peer`. The cause is now removed: binding a loopback port in the test server and the probe of an unused port share one lock, so no server can take the port while the probe connects (`with_unused_port`). A new test starts a server during a probe and requires that it waits; with the lock taken out of `Server::start` that test fails (checked), and the 116 tests of the crate pass with it. Limit: the lock covers the servers of one test process; another program binding a port at that moment is not covered, and the new test measures a wait of 300 ms, so on a very slow machine it could pass without the lock (it cannot fail with it).

## [0.2.0] - 2026-11-19

### Changed

- **Libraries must change `engine = "0.1"` to `engine = "0.2"` in `anaquel.toml`.** Before 1.0 a library needs the same minor line as the engine, so engine 0.2 refuses a library that says `0.1` (error AQ0102, "this library needs engine 0.1"). Nothing else in the library format changed in this release; the new keys and folders (`shelves/`, `language` and `translations` in `volume.toml`) are optional. The four libraries in `examples/` and the `folio` theme now say `0.2`.

- Release archives: from the next release the Linux archives are `.tar.gz` (`anaquel-x86_64-unknown-linux-gnu.tar.gz` instead of `.tar.xz`, and likewise for musl and ARM64), which the coming `anaquel upgrade` reads with a small pure-Rust library; the Windows archives stay `.zip`, the format winget documents. `dist plan` lists the five archives with these names, and the install smoke test of CI builds, unpacks and runs each of them. Limits: the released 0.1.x archives keep their old names; anyone who unpacked a Linux `.tar.xz` by hand now needs `tar -xzf`; whether winget or Scoop would also accept a `.tar.gz` was not established, only that `.zip` is the format their documentation names.

### Added

- `anaquel upgrade [--check] [--version X.Y.Z [--allow-downgrade]] [--rollback]`, the command that replaces the program with a newer signed release (design in `docs/decisions/0005-upgrade-command.md`). In this order, and nothing on the disk changes before the last step: it refuses a program that Scoop, winget or the system package manager owns, or whose folder cannot be written to; it downloads the signed release information and its signature (each with a size limit) from the project's GitHub releases and verifies the signature with the two keys built into the program before reading it; it asks the trust rules what to do (expired, older than a manifest seen before, withdrawn, a downgrade nobody asked for, a foreign address and a missing file for the platform are refused with the reason) and remembers the manifest's time only when the manifest may be believed; it downloads the one archive beside the program, checking its size and SHA-256 against the signed manifest as the bytes arrive; it takes only the program out, runs it with `version` and requires it to answer `anaquel` and exactly the version the manifest promised; only then it swaps it in, keeping one previous version. `--check` does the same without the last steps; `--rollback` runs the previous program the same way and puts it back (running it again goes forward). The program knows its platform from the target it was built for (`x86_64-unknown-linux-musl` is not `-gnu`). The library parts are `procedure` (the order), `report` (the words) and `probe` (the program check), with the exit code 1 for a refusal and 2 for a failure. Tests: 32 on the procedure against a scripted network, a scratch folder, real archives (`.tar.gz` and `.zip`) and a manifest signed with a key made for the test, covering every refusal, a tampered or foreign-signed manifest, a changed, longer and shorter archive, a program that fails its check, files left by a crash and a rollback; 8 that start, wait for and kill real processes; 6 on the real program, including a real rollback of a running program on Windows. Mutation runs on the three modules left only equivalent mutants. Limits: no published release has a signed manifest, so against the real address the command stops with "status 404" today (checked by running it); the whole installation has been run only against a scripted network, never against a real release; a real `dist` archive was not read by this code yet; `--check` does not test whether the folder can be written to, since that writes a file; without a state folder (no `HOME` or `LOCALAPPDATA`) an old manifest replayed later cannot be told from a new one, and the command says so; a proxy in the environment is honoured; Linux, musl and ARM only by CI; the optional once-a-day notice, and the Scoop and winget packages, are not built.
- `Timestamp::from_unix_seconds` in `anaquel-update` (moved from `anaquel-sign`, with its tests), so the command and the manifest writer share one calendar conversion.
- `anaquel-upgrade` gets the download client of the coming `anaquel upgrade`, in a module that is the only one touching the network: `ureq` 3.5.1 (the newest more than two weeks old) with `rustls`, the `ring` provider and the root certificates bundled in `webpki-roots`, so nothing depends on the system's certificate store, `curl` or PowerShell. The release policy admits only `https` to `github.com`, `objects.githubusercontent.com` and `release-assets.githubusercontent.com` (compared whole, no user name, no port), on every hop: redirects are followed by this code, at most five, each address checked before anything is sent, and the HTTP library is told not to follow any. A body is cut off at the limit the caller states (a declared length over it is refused before the body is read), a time limit covers the whole download, and nothing but `User-Agent` identifies the client. The tests run it against a scripted server on the loopback interface (a policy built only by code, never by a setting) and cover every refusal, every redirect status, the limit exactly and one byte over, a body that ends early, a server that never answers and a sink that fails; a mutation run on the module left only the size of the copy buffer unobserved (two more mutants end in an endless loop and are stopped by the time limit). `deny.toml` admits CDLA-Permissive-2.0 for the crate `webpki-roots` alone. Limits: nothing in the program links it yet, so `THIRD-PARTY.md` does not list the new crates until it does; one test downloads a real release file over real TLS and is skipped by default (`-- --ignored`), and it was run on Windows only; whether `ring` builds on Windows ARM64 and musl, and whether `cargo deny` accepts the exception, are shown only by CI; a proxy set in the environment is honoured for the real client; a download that fails half way leaves its bytes in the destination for the caller to discard.
- `anaquel-upgrade` also reads the Windows release archive, a `.zip`, with the `zip` library at version 9.3.0 (the newest more than two weeks old; the library publishes almost daily) and only its deflate method, with no encryption, bzip2, lzma, zstd or xz. The rules are those of the `.tar.gz` reader: only the program is written, at the top or one folder down; links, folders and a repeated name are refused; the program is limited to 256 MiB however well it compresses; the sizes the files declare are added up and limited to 512 MiB before anything is read; nothing is left behind when a read fails. A zip lists its files at its end, so the reader needs the whole archive file and takes a reader that can seek. Limits: the sizes a zip declares are what its headers say, and only the one file read is checked against what it really holds; the library adds 14 entries to `Cargo.lock`, most of them for other systems (WebAssembly, `nix`); Linux and ARM only by CI.
- Crate `anaquel-upgrade`, the file work of the coming `anaquel upgrade`; nothing calls it yet and it never touches the network. It takes the program out of a `.tar.gz` release archive without unpacking the rest (the program may be at the top or one folder down; links, folders and a second file with the same name are refused; the program is limited to 256 MiB and the expanded archive to 512 MiB, so a small archive that expands enormously cannot fill the disk; nothing is left behind on any failure), swaps a new program in beside the installed one keeping exactly one previous version (a failed step is undone, and a failure of the undo says where the old program now is), goes back with `rollback` (twice goes forward again), checks that the folder of the program can be written to, names Scoop, winget or the system package manager when the program sits where one owns it, and remembers the newest manifest time ever accepted in the user's state folder (`%LOCALAPPDATA%\anaquel` or `$XDG_STATE_HOME/anaquel`, else `~/.local/state/anaquel`) so an old manifest cannot be replayed; a damaged state file is reported and never silently replaced. Limits: `.tar.gz` (Linux) and `.zip` (Windows) are read, and no other format; the owner of a program is judged from its folder names only; a rollback that cannot rename the newer program to `.previous` removes it, so that one is not kept; Windows rules were run on Windows only, and Linux, musl and ARM only by CI.
- `anaquel-sign manifest --dir DIR --version X.Y.Z`: writes `release-manifest.json` from the archives `dist` built (`anaquel-TARGET.tar.gz` or `.zip`), so nobody types a hash. It computes each archive's SHA-256 and size and requires the `.sha256` file beside it to agree (a swapped or damaged archive stops it), keeps the releases and advisories of `--previous` unchanged, refuses another channel, an earlier issue time or a version already listed, checks the download address is under the project's own release address (`https://github.com/saidcveltran/anaquel/releases/download/`, no `//`, `.` or `..` segment), takes the times from the clock (`--valid-days`, 60 by default and at most 365) or from `--published`, `--issued` and `--expires`, and parses the result with the program's own manifest reader before it is saved. It never replaces a file. Limits: it signs nothing (`sign` is a separate step); `--previous` is checked for shape, not for a signature; it does not mark a release withdrawn or write advisories (they are carried over, and added by editing the file); only `.tar.gz` and `.zip` archives are listed; dates beyond the year 9999 are refused.
- Design page `docs/decisions/0005-upgrade-command.md`: the design, accepted, of `anaquel upgrade` (`--check`, `--rollback`), which fetches the signed manifest, downloads and checks one archive and swaps the program keeping one previous version. It contacts nothing unless the user runs it, apart from an optional once-a-day notice that is off by default. Limits: the command is built (see above) but the notice is not, and it is the riskiest part and may be dropped.
- Release targets: the release plan now also covers a static Linux x86_64 build (musl), Linux ARM64 and Windows ARM64, besides Windows x86_64 and Linux x86_64. CI runs the tests on both ARM runners (native) and against musl, and builds, unpacks and runs the release archive of all five targets; the musl archive is checked to have no dynamic dependencies. Windows ARM64 is built on a native ARM runner, not inside the third-party cross-build image `dist` uses by default. Limits: these archives appear only with the next release, and nobody has downloaded and run them yet; the static build was not run on another distribution such as Alpine; the installers (`.sh`, `.ps1`) were not tried on ARM.
- The two release public keys (active `FE3C7F0BC0CD1CD3` and reserve `37BA8498688F09C1`, made with `anaquel-sign keygen`) are embedded in `anaquel-update` as `TrustedKeys::release()`. A test verifies a manifest signed once with each real private key, so the lines are shown to be the public halves of those keys. Limits: `anaquel upgrade` now calls it; both private keys are on the maintainer's PC, so a lost disk loses both; the signed fixtures are on the `fixture` channel and expire on 2026-11-20, so no real client accepts them.
- Design page `docs/decisions/0004-web-panel.md`: the design, accepted and not built, of a web panel (`anaquel studio`) to manage and edit the documentation on a server the user runs, in phases from a local single-user editor to accounts, history and change requests. Limits: nothing exists yet; running the panel itself on Cloudflare Workers is a later phase, not promised.
- Shelves: a folder `shelves/NAME/` with a `shelf.toml` (`title`, `description`, `weight`) holds volumes under `shelves/NAME/volumes/`, and each volume is served at `/NAME/VOLUME/`. Volumes in `volumes/` still work, and the home page lists them first, then each shelf with its title. `examples/multi-shelf` shows both. Limits: there is no page at `/NAME/` (only the volumes under it have pages); a shelf and a loose volume with one name are an error; a shelf with no volumes is not shown; the page and link rules are those of volumes, so a shelf name follows the same letters, digits, `-` and `_`.
- `llms.txt`: every build writes a plain Markdown index of the library (title, description, then one `##` section per volume with its pages in reading order, shelved volumes headed `Shelf: Volume`). Links are absolute when `base_url` is set and start with `/` otherwise. Limits: it lists titles and one-sentence descriptions only, not page text (no `llms-full.txt`); drafts are left out; there is no way yet to switch it off or to hide a page from it.
- `anaquel relocate FROM TO` (alias `mv`, paths relative to `--root`): moves a page, adds its old address to the page's `aliases`, rewrites the inline links and reference definitions that point at it, and writes only when a full build of the result has no error; `--dry-run` prints the plan. Moving a folder's `_index.md` moves the folder. Refusals are AQ0901 to AQ0905. Limits: a page with a card of relative `href` does not move between folders, and an `aliases` list with a comment or a file with mixed line endings stops the move (AQ0904); static files move only with their folder and leave no redirect (the plan says how many); a crash in the middle of a write is not undone (a failed write is) and can leave files named `.anaquel-held-NNNNNN` or `.anaquel-staged-NNNNNN`, which stop a later move that needs the same name until they are deleted; a move that cannot remove an original it held says so and is not undone; a source file whose name on disk is not in Unicode normal form C may be reported as not found (not tested); the Windows rules and the case-insensitive folder rule are checked on every system and tested on Linux and Windows, not on macOS. The write keeps every moving file under a held name until all are in place, uses `create_new` for every new file so a link planted at a temporary name is never written through, reads the disk (not only the library's list) for what is already at the destination and for folders that differ only by case, and the plan names the folders removed when empty; the previous build's ledger is not read, a before and after comparison of every address is used instead. Every new text is staged beside its source with the permission bits of the file it replaces, every source is vacated before any destination is filled, a file that changed since the library read it stops the move, and a step that cannot be undone is named with the place its file belongs in. A file left by an earlier stopped move, or a folder that cannot be listed, is refused before anything is written. Known limits: a file created at a destination by another program between the check and the rename is replaced (a rename that refuses to replace is not used yet); hard links, access control lists and extended attributes are not preserved; a page Windows keeps read-only cannot be rewritten and the move is undone.
- Crate `anaquel-update`, the trust core of the coming `anaquel upgrade`: it verifies a detached minisign signature of `release-manifest.json` before reading it, then chooses a release and refuses an expired manifest, one older than a manifest already seen, a withdrawn release, a downgrade nobody asked for, a missing file for the platform and a download address outside the project; it also checks a download's SHA-256 and size. Limits: a library only, not called by any command yet; no network, clock or file access; it embeds no keys (the real keys are not generated yet); only prehashed signatures are accepted; times compare as text in UTC `Z` form.
- `anaquel-sign`, the maintainer's tool for release signing keys (design in `docs/decisions/0003-release-signing-keys.md`): `keygen` makes a key pair protected by a passphrase of at least 12 characters with at least 6 different ones (compared in Unicode normal form C), and `sign --key FILE --public FILE` signs `release-manifest.json` only with the private key the public key file names, after checking that the program would accept the manifest and that the new signature verifies with the shipped verifier; a file that fails while being written is removed. Public keys and signatures are minisign files. Limits: it is built from the repository and is not in the release archives; the private key file is its own format, not readable by the official minisign program, and a test pins its exact bytes; the terminal prompt is not driven by a test and the file permissions on Windows were not checked (`keygen` prints a reminder there); an already expired manifest is not warned about when signed; no real keys exist until the maintainer runs `keygen`.
- Design page `docs/decisions/0002-relocate-and-aliases.md` for `anaquel relocate` and aliases.
- Languages: `volume.toml` takes `language` (a BCP 47 tag; the library's `language` when absent) and `translation_of` (the address of the original volume, `slug` or `shelf/slug`). Pages of a translation are paired with the original by their path inside the volume; each page then lists its other-language pages as `<link rel="alternate" hreflang>` (only with a `base_url`, since the links must be absolute) and as a language list in the sidebar. `<html lang>` follows the volume. The texts of the `folio` theme (skip link, menu, previous, next, on this page, 404) come in English and Spanish by the primary subtag of the page language; any other language reads English. A bad tag, an unknown or self-referencing `translation_of`, a translation of a translation, or two volumes of one book in one language is error AQ0101 at the `volume.toml`. Limits: no `x-default`; a page missing from a translation simply lists no alternates; the home page and the 404 page follow the library language; the theme texts exist only in English and Spanish; whether the search index separates pages by language was not checked.

## [0.1.1] - 2026-11-18

Theme changes and the end of macOS support. The engine has no code change.

### Changed

- The READMEs no longer present Cloudflare Workers as the target: Anaquel builds a static site that any web host can serve, and the program runs on Windows and Linux. The `_headers` and `_redirects` files are in the format Cloudflare reads; other servers need the rules copied by hand. They also say that no upload to any host has been tried, and list the planned extra builds (musl, Linux ARM64, Windows ARM64) and a self-hosted web panel as planned, not built.
- Theme `folio`: a jump to a heading on the same page scrolls smoothly; it stays instant under reduced motion or with `data-motion="off"`.
- Theme `folio`: jumps to a heading last 200 to 400 ms in every browser, move focus to the heading, and Back and Forward restore the position at once. Limits: the script adds about 9 KB before compression; Firefox and Safari were not run; the cases are in `docs/folio-browser-cases.md`.
- Theme `folio`: every page writes an animated logo and a greeting to the browser console. Limits: the script grows to about 19 KB before compression (about 5.5 KB after); Firefox and Safari were not run; the cases are C1 and C2 in `docs/folio-browser-cases.md`.

### Fixed

- The public gate in CI read the co-author trailer that GitHub adds to a squash merge as a trace of an AI tool and failed every pull request. It now accepts that trailer when its address is a public GitHub identity. Limit: the line that caused it stays in the history of `main`, which was not rewritten.

### Removed

- macOS support. CI no longer runs on macOS (its runners often got no machine and the jobs were cancelled after 15 minutes), and the release workflow builds archives for Windows x86_64 and Linux x86_64 only. Known limits: nobody builds or tests Anaquel on macOS or on any arm64 system; 0.1.0 keeps its two macOS archives but they are no longer kept up; the installer scripts of later releases will offer no macOS archive.

## [0.1.0] - 2026-11-18

First release.

### Added

- Engine core: schema, directive, catalog, compose, theme, assets, render, emit, search port and pipeline crates.
- `anaquel` command line: `new`, `build`, `check`, `serve`, `doctor`, `version`; `--strict` turns warnings into errors.
- Local preview server bound to `127.0.0.1`, with a `Host` check, path sanitising and reload on change.
- The preview server applies the `/*` rule of the built `_headers` file, so the Content-Security-Policy is the same locally as in production.
- `anaquel serve --search` indexes on every rebuild.
- `folio` theme with a bounded navigation tree, dark and light tokens and a CSP without inline code.
- Literata is bundled (WOFF2, 130 KB); stylesheets may name other theme assets with a placeholder that the build replaces with the fingerprinted URL.
- `examples/reference-library`: an invented library of 271 pages that must check with no diagnostics.
- CI for Linux, Windows and macOS (format, clippy, tests, sample library, the five-minute example of the README) and a licence and advisory check with `cargo-deny`.
- `tools/check_images.py`: refuses image metadata (extra PNG chunks, editor data in SVG) and runs in CI; `--fix` rewrites a PNG without it.
- README in English and Spanish with banner, screenshots for both colour schemes, feature table, install table, comparison and a list of cases where Anaquel is the wrong choice.
- Issue forms (bug, feature, translation, documentation), a pull request template and the Contributor Covenant 2.1 as `CODE_OF_CONDUCT.md`.

- Release setup with `dist` 0.34.0 (`dist-workspace.toml`, `.github/workflows/release.yml`): archives for Windows x86_64, Linux x86_64 and macOS (Intel and Apple Silicon), a shell and a PowerShell installer, a SHA-256 sum per archive and a GitHub build attestation. The workflow builds only when a version tag is pushed; on pull requests it only plans. No tag has been pushed and nothing has been released.
- `tools/install_smoke.py` and an `install smoke` CI job on three systems: build the release archive, check its SHA-256, unpack it into an empty folder and run `version`, `new`, `check --strict` and `build` with the unpacked program.

- Directives: `:::name attributes` ... `:::` blocks, nested by using fewer colons inside. The set is closed: `hint` (info, success, warning, danger), `details` (title, open), `tabs` with `tab` (title; `sync` makes groups follow each other and remembers the choice), `cards` with `card` (title, href, image; `cols` 1 to 4), `steps` with `step`, `columns` with `column` (`width` 1 to 6) and `embed` (YouTube and Vimeo over https, rewritten to the privacy-friendly player in a sandboxed frame). An unknown, unclosed, misplaced or malformed directive is error AQ0801 with its line; nothing inside a fenced code block is read as a directive; limits are 6 levels deep and 500 blocks per page. Markup is fixed in the engine and every value that content supplies is escaped.
- The built `_headers` file forbids all frames (`frame-src 'none'`) unless a page embeds a video, and then allows only the origins that pages use.
- `examples/directives`: one page per directive with its source and its result; CI checks it with `--strict`.
- Theme styles for every directive in both colour schemes, and a small script that turns the tabs into an accessible tab list (arrow keys, Home, End). Without the script every tab is shown under its title.

- Headings inside directive blocks get their anchors; the heading list is read in the same order the page is composed.
- Syntax highlighting of fenced code with `syntect` 5.3.0 (pure Rust regex engine, no C code). The output uses class names only, so the Content-Security-Policy is unchanged; the theme colours them in both schemes. Blocks over 100 KB, unknown languages and grammar failures stay plain escaped code. `shell`, `console` and `csharp` are accepted as names.
- `tools/third_party.py` writes `THIRD-PARTY.md` from `cargo tree`; CI fails when the file is out of date.

- A hand-written attack suite (`crates/anaquel-pipeline/src/xss.rs`): hostile text in every place that accepts text must build into pages that a tag scanner finds clean (only listed tags, no event or style attributes, no script with a body, no dangerous URL, frames only from the sandboxed video players); about 100 payloads (script, data, file and protocol-relative links, entity and tab tricks, raw HTML of every kind, directive abuse, bad embed hosts, hostile front matter) must each be refused with nothing written.
- Fuzzing: four `cargo-fuzz` targets in `fuzz/` (`directive_grammar`, `front_matter`, `url_policy`, `link_resolver`) and a CI job that runs each for 150 seconds, ten minutes in all, on Linux with a pinned nightly compiler. The checks live in the new crate `anaquel-fuzzcheck`, which also runs them over the seed files and about 20 000 mutations on every system in the ordinary test run.
- `tools/naming_gate.py` refuses crate, folder, file, module and type names that say nothing about their responsibility (`utils`, `helpers`, `common`, `shared`, `types`, `context`, `item`, a `new_` or `old_` prefix, a version suffix, an `impl` suffix); `tools/public_gate.py` looks in the tree and in the commit history for user folders, keys, e-mail addresses that are not public GitHub identities, traces of AI tools and editor metadata in binaries, and takes a private list of names with `--private FILE`; `tools/test_gates.py` tests both. CI runs the three in a `gates` job with the full history.

### Fixed

- The `gates` CI job checked the merge commit that GitHub builds for a pull request, which carries the author's profile e-mail, and failed a clean change. It now checks the pull request at its own head.

- `cargo-deny` rejected the path dependencies between workspace crates as wildcards; `deny.toml` now allows wildcard paths (the crates are not published).

- The theme toggle showed a moon in both colour schemes. It now shows a moon in the light scheme and a sun in the dark one, chosen by CSS only.

- `anaquel serve` rebuilt the site about once a second on Linux with no file changes: `inotify` reports that a file was opened or read, and every build reads all sources. The watcher now ignores access events and acts only on creation, change and removal. Found by a teammate's test on Zorin OS; limit: checked by a unit test of the event filter on Windows, not yet by a long run on Linux.

- Theme `folio`: `@view-transition` sat inside a style rule, where it is dropped, so page transitions never ran; it is now a direct child of the media query. `data-motion="off"` now also turns off transitions, animations and the view transition. Escape closes the menu and returns focus to its button. Tab panels are focusable (`tabindex="0"`). Every code block is a tab stop (`<pre tabindex="0">`), so a keyboard can scroll one that is wider than the screen (found and fixed by a teammate). Limits: nothing in the theme sets `data-motion` yet (no visible switch); the page transition was seen working in Brave on Linux, the other changes were not checked by hand in a browser.

### Changed

- Two types were renamed because the naming gate refused them: `Shared` (preview server state) is now `ServedSite` and `Context` (template input) is now `TemplateInput`.
- Names that become part of an address are checked. A page or folder name, a `slug` and every segment of an alias may hold letters of any script, digits and `- _ . ~ + @`; a space, quote, `#`, `?`, `%`, `&`, `;`, bracket, control or invisible character is an error with the rename to make (a page may set `slug` instead of renaming the file). Before, a file called `c#.md` or `my page.md` was written under an address that browsers read differently, and an alias with a quote or `<` passed `check` and then failed to write on Windows. Static files may not have `#`, `%` or `?` in their names. This can turn a library that built before into one that does not; the messages say which name to change.
- A leading `# Title` that repeats the page title is left out of the page body, because the theme already prints the title. A `#` heading that says something else, or that is not the first block, stays.
- Only pages named `terms.md` or `glossary.md` define terms. A `###` heading in ordinary prose used to define one and made duplicates an error.
- `CHANGELOG.md` follows Keep a Changelog 1.1.

### Known limits

- CI runs on Linux, Windows and macOS: format, clippy, tests, the sample library, licences and advisories, an install smoke test of the release archive, a 10-minute fuzz run on Linux, and the naming and public gates.
- The theme was looked at in screenshots at desktop width in both colour schemes, at 500 px by the author, and at 390 px by a teammate in Chromium on Linux (light scheme on every directive page; dark scheme only for hint and code blocks). Other browsers, Safari on iOS and dark-scheme cards, columns, tabs, steps and details at 390 px were not checked. The keyboard and reduced-motion review is written but not run.
- The search UI was checked by script in a browser: results appear and there is no CSP violation.
- Search needs the external `pagefind` program; it is not linked into the binary (the library tree is large and contains C code).
- The `indexing_slicing` lint is not denied yet.
- The embedded Literata font is a Latin subset (Western European); text in other scripts falls back to system serif fonts.
- Theme UI strings are English only; translation arrives with the language work of M2.
- The crates are not publishable yet: the theme files live outside the crate folders.
- The conduct contact is the private security channel of GitHub, because the project has no public mailbox.
- Publishing to Cloudflare Workers is not documented or tested.
- The release archives are not signed by Windows or Apple (no spending), so SmartScreen and Gatekeeper will warn. `dist` builds the archives and installers when a tag is pushed; the CI install smoke test builds, unpacks and runs the archive of each system, but the installer scripts and `gh attestation verify` have not been checked against real release files. There are no minisign signatures, no `upgrade` command and no `version --verbose` with the tagged commit yet (M2).
- There is no Linux arm64 archive.
- Directive limits: the opening line must start at column 0 with the name right after the colons; a fenced code block indented by four spaces or more is not tracked, so a `:::` line inside one is read as a directive. `include`, `variables` and `updates` are not implemented. The tab script and the directive styles were looked at in screenshots at desktop width only; the embed frame was seen to load, but playing a video was not tested. Pages without `description` still get one made from the whole page text, which starts with the title.
- Highlighting uses the grammars bundled with `syntect`: there is none for TOML, TypeScript, JSX, PowerShell, Dockerfile, Kotlin, Swift or INI, so those blocks are shown plain. Adding grammars means bundling and licensing more files; not done.
- The attack suite checks the output with a scanner written for it, not with a browser. It does not run script and does not cover browsers' own parsing quirks beyond the cases listed in it.
- Images may come from any https address (`img-src` allows `https:`), so a page can make a reader's browser contact another site. An SVG file in a library is copied as it is; the site-wide Content-Security-Policy is what stops script in it, and only when the host serves the `_headers` file.
- The fuzz targets run only in CI on Linux (Windows cannot link the libFuzzer runtime); on the other systems a smoke test replays the corpus. The first CI runs stopped the `url_policy` target twice on inputs that were false alarms of the check itself (a page that shows the words `formaction="vbscript:` as text, and a code fence whose information string ends up quoted in a `class` attribute); the check now reads real attributes inside tags, and both inputs are seeds. The last run of ten minutes passed. Ten minutes is a floor, not a guarantee: the parsers have not been fuzzed for hours.
- The public gate in CI cannot know the private names of a maintainer; those are checked only where the maintainer runs it with `--private`. The naming gate reads type names with one line-by-line pattern, not a Rust parser, so an item declared in an unusual layout is not seen.
